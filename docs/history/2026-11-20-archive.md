**接手概况**

目标是让会议室实时麦克风语音经过增强和去混响后听起来自然、清晰，并在 RK3588 上持续实时运行、尽量降低延迟。用户仍觉得部分输出浑浊、发虚，听起来像有细小噪声，尚未确认满意。

已经实现 UL-UNAS CPU → NVIDIA 原权重单步 NPU → 实时 v4。整链 PCM 输入到输出 P95 约 190–191 ms。NVIDIA 已经能实时运行，当前重点是音质取舍和分块敏感性。原始 50 步离线版本仍是质量参考。

目前没有一套参数在全部实录上全面胜出。原单步在 002、g4e 的全段 DNSMOS 最高。动态复数混合明显减轻分块起伏，在部分模拟数据里也有更强的尾音抑制。轻度混合在 dut10 的人声指标较好，去混响较弱。接手后需要继续用试听判断。

**正式 NVIDIA C 源码仍含高斯采样项。** 11-19 的禁高斯和音质改动均位于本地 out 目录，尚未收敛到正式构建入口。这是接手后首先需要处理的配置差异。

NVIDIA 来源为 se_der_sb_16k_small，具备语音增强和去混响能力。导出沿用原权重，固定第一次采样条件 t=1、静态 T16，等价改写 GroupNorm。输入为 1×2×256×16 复数频谱，RKNN FP16，Runtime 2.3.2，近期板端 NPU driver 0.9.8。

NVIDIA 使用 FFT 510、STFT hop 128、Hann 窗，幅度平方根压缩后乘 0.33。模型窗 120 ms，32 ms 历史、8 ms 交叠、每 80 ms 推进。UL-UNAS 另用 FFT 512、hop 256。v4 使用因果 EQ、流式音量控制、软门限和限峰，按 256 点输出。

**8. 实验代码和模式**

主要源码为 [nvidia_sb_speech_preserve.c](/home/xh/itc_project/superlin/SL-clearVoice/out/nvidia-speech-preserve-20261119/nvidia_sb_speech_preserve.c)。模式编号仅对该实验实现及派生实现有效。

| 参数 | 含义 |
| --- | --- |
| SB_RKNN_CORE_MASK=3 | NPU 核 0/1 |
| SB_TAIL_POLICY=5 | 持续强抑制信号和输入电平共同控制尾音力度 |
| SB_SPEECH_MODE=9，SB_DRY_GAIN=0.025 | 原单步复数重建，高斯关闭，加少量原输入 |
| SB_SPEECH_MODE=8，SB_DRY_GAIN=0 | 动态复数混合，说话段 NVIDIA 占比约 56%，高频逐渐降至约 30%，强尾音可增至 100% |
| SB_SPEECH_MODE=10，SB_DRY_GAIN=0 | 固定 35% 复数混合 |
| SB_SPEECH_MODE=11，SB_DRY_GAIN=0 | 固定混合加停顿统一衰减，额外上限 5.5 dB |
| SB_SPEECH_MODE=12，SB_DRY_GAIN=0 | 同法，额外上限 11 dB |

## 2. 高斯采样是不是噪声来源

NVIDIA 的随机 SDE 采样会注入高斯扰动，官方实现也提供不注入随机项的 ODE 路径。原生多步采样中的噪声属于算法的一部分。当前单步实现删除末端高斯项属于单步均值重建，不能把这一改动称为完整的官方 ODE 求解器。[官方采样源码](https://github.com/NVIDIA/NeMo/blob/v2.3.0/nemo/collections/audio/parts/submodules/schroedinger_bridge.py)

当前目标为干净、自然的实时输出，正式入口默认关闭末端高斯项。此前 DUT 开关对照静音区平均能量差约 0.02 dB。本轮对已降噪 g4e 复用完全相同 RKNN 张量，仅恢复原高斯项作对照，整段差值为 -71.64 dBFS，相对输出 -44.60 dB。以输入低于 −65 dBFS 的 100 ms 窗口选择 38.1 秒低电平片段，高斯开/关分别为 -86.11 / -86.27 dBFS，仅相差 0.154 dB。

两次均为DUT完整105.808秒的16ms输入节拍回放，输出均为1,692,928点。T32生产包由原生产C程序和启动脚本派生，日志明确 `gaussian_sampling=false`；本次827块全部在128ms预算内。候选生产输出与前一轮实验原生整链相关系数大于0.999999999，差值能量约低97.6dB。物理声卡和会议程序缓冲仍未计入这里的PCM延迟。

T32候选使用全部三个NPU核，T16基线使用两个核。短段双核T32探针平均服务时间约129.5ms，超过128ms推进预算，因此本候选的实速结果对应mask=7，不能直接套用到双核部署。

六份全段T32音质输出都经过板端NPU；DUT的NVIDIA中间级从该次板端捕获张量重建，其余为板端原生文件输出。FP32与NPU的全段数值核对见 [t32-numeric-check.json](out/nvidia-context-steps-20261120/t32-numeric-check.json)，当前证据仍支持优先检查窗口和推理组织，而不是把明显金属感主要归因于RKNN精度。
